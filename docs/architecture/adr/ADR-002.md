# ADR-002 — ProjectState

| Field | Value |
|-------|-------|
| **ADR Number** | ADR-002 |
| **Title** | Introduce ProjectState as single immutable state container |
| **Status** | Accepted |

## Context

Multiple platforms currently exchange arbitrary objects, partial DTOs, and ad-hoc context bags through the production handler.

## Problem

Platforms exchange arbitrary objects. No single source of truth for project progress, versioning, or replay.

## Alternatives

1. Shared mutable context object (race conditions, no replay)
2. Event-sourcing only (complex without snapshot)
3. **Immutable ProjectState with snapshots** (accepted)

## Decision

Introduce **ProjectState** — a single immutable container holding all specification chain outputs, metadata, and version history.

## Reason

Single immutable state enables deterministic replay, rollback, and tracing.

## Consequences

- Replay of any pipeline stage
- Rollback to prior snapshot
- End-to-end tracing via DecisionTrace

## Migration

See Part 19 Wave 01–02, Part 13 (DTO-001/002), RFC-001.

## Affected Files

- `src/lib/runtime/ProjectState.ts` (create)
- `src/lib/runtime/ProjectSnapshot.ts` (create)
- `src/lib/runtime/ExecutionContext.ts` (create)
- `src/lib/generate-infographic-handler.ts` (eventually consume ProjectState)

## Acceptance

Project compiles. ProjectState is immutable. All new modules read/write through official contracts only.

## Rollback

Remove ProjectState runtime module; retain legacy handler context passing.
