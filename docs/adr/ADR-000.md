# ADR-000 — Template

| Field | Value |
|-------|-------|
| **ADR Number** | ADR-000 |
| **Title** | Architecture Decision Record Template |
| **Status** | Accepted |

## Context

Design AI Operating System requires every architectural change to be documented with rationale, consequences, and rollback path.

## Problem

Undocumented decisions lead to inconsistent implementation, lost context, and untraceable migrations.

## Alternatives

1. Document decisions only in Architecture Bible (monolithic, hard to trace per decision)
2. Document decisions in pull request comments (ephemeral, not searchable)
3. **ADR files** (accepted — one file per decision, versioned in git)

## Decision

Use this template for all ADRs under `docs/architecture/adr/`.

## Consequences

**Positive:** Traceability · Reviewability · Rollback clarity · Links to Implementation Directives

**Negative:** Maintenance overhead for each architectural change

## Migration

Copy this template to `ADR-NNN.md`, fill all fields, link from Architecture Bible and related RFCs/Directives.

## Affected Files

- `docs/architecture/adr/ADR-NNN.md` (new decision file)
- `docs/DAOS_Specification.md` (summary reference)
- Related Implementation Directives

## Acceptance

ADR file exists, status set, linked from Bible and at least one Implementation Directive.

## Rollback

Mark ADR as **Superseded** by new ADR; do not delete historical records.
