# RFC-005 — RenderGraph

| Field | Value |
|-------|-------|
| **RFC Number** | RFC-005 |
| **Title** | RenderGraph |
| **Author** | Architecture Team |
| **Status** | Accepted |

## Motivation

Full pipeline restart on render failure wastes provider quota and increases latency.

## Architecture

- `RenderGraph` — DAG of render stages
- `RenderNodes` — background, composition, shadow, export nodes
- `RetryEngine` — per-node retry policy
- `NodeScheduler` — dependency-aware execution

Input: `RenderBlueprint` only. No business or creative logic in render layer.

## Implementation

Wave 07. Extract business/creative/prompt from render-engine first; then introduce graph.

## Migration

Monolithic render sequence remains as fallback until graph passes audit tests.

## Alternatives

- Whole-pipeline retry (status quo, rejected)
- External workflow engine (deferred — YAGNI)

## Compatibility

Additive; graph opt-in then default.

## Risks

- Node dependency cycles
- Partial state on failed retry

## Acceptance

Node-level retry without full restart. Rendering executes RenderBlueprint only.
