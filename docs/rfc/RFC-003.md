# RFC-003 — Knowledge Engine

| Field | Value |
|-------|-------|
| **RFC Number** | RFC-003 |
| **Title** | Knowledge Engine |
| **Author** | Architecture Team |
| **Status** | Accepted |

## Motivation

Knowledge is duplicated across design, memory, and platform modules. A unified engine is required as single source of truth.

## Architecture

- `KnowledgeRuntime` — execution entry
- `KnowledgeQuery` — typed query API
- `KnowledgeGraph` — relational knowledge store
- `KnowledgeSpec` — immutable platform output

## Implementation

Reuse existing `src/lib/design/` (genome, registry, patterns, rules). Wave 03 introduces runtime wrapper — **do NOT rewrite** existing logic.

## Migration

Wrap existing APIs; deprecate duplicate DTOs in Wave 10.

## Alternatives

- Full rewrite of knowledge module (rejected per Part 19 Wave 03)
- External knowledge DB only (rejected — loses graph traversal)

## Compatibility

Existing tests must pass; new API additive first.

## Risks

- Query API scope creep
- Graph consistency under concurrent updates

## Acceptance

Knowledge Platform produces one immutable `KnowledgeSpec` output.
