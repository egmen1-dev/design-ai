# RFC-001 — ProjectState

| Field | Value |
|-------|-------|
| **RFC Number** | RFC-001 |
| **Title** | ProjectState |
| **Author** | Architecture Team |
| **Status** | Accepted |

## Motivation

Platforms need a single immutable container for the specification chain. Arbitrary object passing prevents replay, rollback, and audit.

## Architecture

- `ProjectState` — immutable root state
- `ProjectSnapshot` — point-in-time copy for version history
- `ExecutionContext` — runtime metadata (run id, timestamps, trace ids)
- All specifications attached as typed, frozen DTOs

## Implementation

1. Wave 01: create runtime skeleton
2. Wave 02: introduce contracts and wire ProjectState
3. Legacy handler adapts via thin bridge until Wave 10

## Migration

Existing handler continues; new `runDesignAiBookPipeline()` consumes ProjectState incrementally per Part 19.

## Alternatives

- Mutable shared context (rejected — no immutability)
- Full event sourcing without snapshots (rejected — complexity)

## Compatibility

Non-breaking during Wave 01–02 (parallel path). Breaking when legacy handler removed (Wave 10).

## Risks

- Dual-path maintenance during migration
- Snapshot storage size

## Acceptance

ProjectState immutable. All new modules use official contracts. Replay and rollback demonstrated in tests.
