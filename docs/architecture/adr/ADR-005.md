# ADR-005 — Knowledge Engine

| Field | Value |
|-------|-------|
| **ADR Number** | ADR-005 |
| **Title** | Create unified Knowledge Engine |
| **Status** | Accepted |

## Context

Design knowledge (genome, patterns, rules, memory) is spread across `src/lib/design/`, `src/lib/memory/`, and platform-specific caches.

## Problem

Knowledge duplicated across modules. No single query API or graph.

## Alternatives

1. Keep distributed knowledge stores (duplication continues)
2. Database-only knowledge (loses in-memory graph benefits)
3. **Unified Knowledge Engine** (accepted)

## Decision

Create unified **Knowledge Engine** with `KnowledgeRuntime`, `KnowledgeQuery`, `KnowledgeGraph`, and `KnowledgeSpec` output.

## Reason

Knowledge becomes single source of truth (Part 17, Part 18).

## Consequences

- One immutable `KnowledgeSpec` per query cycle
- Platforms query knowledge; they do not own duplicate stores
- Learning Platform can update graph automatically

## Migration

See Part 17 (KNG-001/002), Part 19 Wave 03. **Reuse existing implementation — do NOT rewrite.**

## Affected Files

- `src/lib/design/` (extend)
- `src/lib/platforms/knowledge/` (create or extend)
- `docs/Architecture_Bible.md` Part 17

## Acceptance

Knowledge Platform produces one immutable output. No duplicate knowledge DTOs.

## Rollback

Revert to per-module knowledge access; mark ADR Superseded if replaced.
