# ADR-001 — Prompt Driven Architecture

| Field | Value |
|-------|-------|
| **ADR Number** | ADR-001 |
| **Title** | Replace Prompt Driven Architecture with Specification Driven Architecture |
| **Status** | Accepted |

## Context

The legacy pipeline encodes design knowledge, commercial strategy, and creative decisions inside natural-language prompts sent to image providers.

## Problem

- Prompt contains all knowledge
- Knowledge is lost during translation to prompt
- Prompt is not versioned
- Prompt cannot explain decisions

## Alternatives

1. Improve prompt templates (does not fix information loss)
2. Add prompt versioning only (still lossy carrier)
3. **Specification Driven Architecture** (accepted)

## Decision

Replace Prompt Driven Architecture with **Specification Driven Architecture**.

Specifications (`ProductBrief`, `ResearchSpec`, `CommercialSpec`, `CreativeSpec`, `VisualBlueprint`, `RenderBlueprint`) are the source of truth. Prompt is generated only at the Provider Adapter boundary.

## Reason

Specifications preserve information. Prompt does not.

## Consequences

**Positive:**

- Versioning
- Replay
- Decision Trace
- Platform isolation

**Negative:**

- Higher implementation complexity

## Migration

See Part 19 Wave 02 (Contracts), Wave 04–07 (platform separation), Part 18 (Prompt module → Provider Adapter).

## Affected Files

- `src/lib/prompt/` (legacy, move to Provider Adapter)
- `src/lib/contracts/` (new specifications)
- `src/lib/platforms/*` (platform outputs)
- `docs/Architecture_Bible.md` (LAW-001)

## Acceptance

No prompt generation outside Provider Adapter. All platform outputs are immutable specifications.

## Rollback

Revert to prompt-driven handler (`generate-infographic-handler.ts` v17.1). Not recommended — violates LAW-001.
