# ADR-004 — RenderGraph

| Field | Value |
|-------|-------|
| **ADR Number** | ADR-004 |
| **Title** | Introduce RenderGraph for node-level render execution |
| **Status** | Accepted |

## Context

Current render pipeline restarts the full generation on any failure (background, composition, shadow, export).

## Problem

Full render restarts after every failure. Wasted provider calls and latency.

## Alternatives

1. Retry entire pipeline (status quo)
2. Manual retry flags per stage (fragile)
3. **RenderGraph with node-level retry** (accepted)

## Decision

Introduce **RenderGraph** with **RenderNodes**, **RetryEngine**, and **NodeScheduler**.

Rendering executes `RenderBlueprint` only; each node can retry independently.

## Reason

Node-level retry reduces cost and improves reliability.

## Consequences

- Partial re-execution on failure
- Clear dependency graph between render stages
- Better observability per node

## Migration

See Part 18 (Render Engine new modules), Part 19 Wave 07, RFC-005.

## Affected Files

- `src/lib/render-engine/RenderGraph.ts` (create)
- `src/lib/render-engine/RenderNodes.ts` (create)
- `src/lib/render-engine/RetryEngine.ts` (create)
- `src/lib/render-engine/NodeScheduler.ts` (create)

## Acceptance

Rendering executes RenderBlueprint only. Failed nodes retry without full pipeline restart.

## Rollback

Fall back to monolithic render sequence in `render-engine`.
