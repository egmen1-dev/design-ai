# RFC-004 — Provider Adapter

| Field | Value |
|-------|-------|
| **RFC Number** | RFC-004 |
| **Title** | Provider Adapter |
| **Author** | Architecture Team |
| **Status** | Accepted |

## Motivation

Prompt generation is scattered across modules, violating LAW-001. Providers must be swappable behind one compiler boundary.

## Architecture

- Single **Prompt Compiler** in Provider Adapter
- Input: `RenderBlueprint` + provider profile
- Output: provider-specific prompt payload
- Templates and provider mapping moved from `src/lib/prompt/`

## Implementation

1. Create Provider Adapter module
2. Move compiler, templates, mapping from legacy `prompt/`
3. Remove prompt builders from design-process, render-engine
4. Architecture validator blocks prompt outside adapter

## Migration

Legacy prompt path remains until Wave 10; new path routes through adapter only.

## Alternatives

- Shared prompt library (rejected — no enforcement boundary)
- Per-provider duplicate compilers (rejected)

## Compatibility

Breaking for modules that generated prompts directly (intentional).

## Risks

- Provider mapping regressions
- Template parity during move

## Acceptance

One Prompt Compiler. Zero prompt generation outside Provider Adapter.
